# UI playground

Локальный стенд реальных renderer-компонентов на синтетических данных.

Из корня репозитория:

```sh
pnpm dev:playground
```

Открыть http://127.0.0.1:5193/.

## Структура

- `App.vue` — точка входа для примеров. Пока содержит только AI-раздел.
- `examples/ai/Preview.vue` — каталог состояний, поиск, ширина, язык и тема.
- `examples/ai/fixtures.ts` — синтетические сценарии.
- `examples/ai/demoState.ts` — потоковая генерация, Stop/Retry, уточнения и очередь со снимками контекста.
- `examples/ai/mocks.ts` — имитация внешних действий.
- `examples/ai/types.ts` — параметры сценариев на основе типов приложения.
- `vite.config.mjs` — отдельная конфигурация и подмена зависимостей.

Новые разделы добавляются в `examples/<feature>/`. Общую навигацию следует
добавить при появлении второго раздела. Компоненты продукта остаются в
`src/renderer/components` и подключаются напрямую; изменения видны через HMR.

AI-примеры используют настоящий `AiPanel` и его дочерние компоненты.
Панель ввода и выбор контекста также настоящие. Подменены Electron,
AI-состояние, навигация, буфер обмена и HTTP runner. Применение и отмена меняют
только демоданные. Стенд проверяет интерфейс, а не бизнес-логику backend.
При добавлении примеров явно подменяйте новые внешние зависимости.

Кнопка «Сбросить пример» восстанавливает исходное состояние. Доступны имитация
ошибки действия и несохранённого HTTP-запроса. Переключатель языка меняет
строки компонентов; синтетические тексты ответов остаются на русском.

Необязательная сборка:

```sh
pnpm exec vite build --config playground/vite.config.mjs
```

## Проверка сценариев

```sh
node playground/check-types.mjs
pnpm exec vitest run playground/examples/ai/demo.test.ts
pnpm exec eslint playground/examples/ai playground/check-types.mjs
```

Проверка типов выводит ошибки только в файлах модели стенда; production-типы
используются как зависимости. Тесты проверяют существующие схемы данных,
согласованность предпросмотра операций и основные переходы состояния.

Новые сценарии должны описывать достижимый вид интерфейса, а не произвольную
комбинацию полей. Сообщения типизированы через `ChatMessage`, HTTP и native
действия — через shared-типы. Параметры `stale`, `dirty`, `configured`, `search`
и `composer` задают окружение примера отдельно от сообщения.

Для проверки дизайна представлены начало работы, контекст, поиск, потоковый
код, уточнения, очередь, review, HTTP-действия, нативные операции и история.
Пример «Потоковый ответ с кодом» запускается при выборе; «Сбросить пример»
повторяет его. После отправки вложения остаются в панели ввода. Очередь
сохраняет собственный контекст; неудачный запуск не удаляет задачу.

Внешние окна предпросмотра, файловые диалоги и HTTP runner не открываются:
стенд показывает их карточки и результаты в панели ассистента. Ответы
синтетические, время и результат сети имитируются. Это проверка UI, а не
сквозной тест Electron или провайдера ИИ.
