# Проверка подсветки языков

Корпус содержит отдельный пример для каждого из 165 уникальных ID каталога massCode. Эти же исходники находятся в папке **qa-language-test** внутри приложения.

```sh
pnpm exec vitest run qa-language-test src/renderer/components/cm-extensions/__tests__/codeHighlight.test.ts
```

Подробный отчёт с токенами, проверенными конструкциями и отличиями от прежнего сопоставления TextMate scopes:

```sh
QA_LANGUAGE_REPORT=/tmp/cm6-language-report.json pnpm exec vitest run qa-language-test
```

## Что проверяется

В `corpus.json` у каждого языка есть исходник, план категорий `requiredCategories` и проверки конкретных диапазонов `checks`. Поле `construct` называет проверяемую конструкцию: например, многострочная строка, числовой литерал или имя функции. Смещения `from`/`to` считаются в UTF-16, как в строках JavaScript; конец не включается.

- Все ID каталога присутствуют ровно один раз. Plain Text остаётся без подсветки.
- Каждая запланированная категория имеет явное ожидание; исчезновение её подсветки приводит к ошибке.
- Каждая фактически выведенная категория также должна иметь проверку конкретного диапазона. Просто добавить длинный код без проверок недостаточно.
- В сумме примеры проверяют все 24 категории общего highlighter.
- `knownGaps` явно фиксирует нераспознанные конструкции прежних грамматик: точный диапазон, нужную категорию и причину. Они остаются в примерах и отчёте. Тест требует перевести такую запись в обычную проверку, когда подсветка исправлена. Зелёный прогон не означает отсутствие этих известных ограничений.
- Ожидаемый класс проверяется на каждом символе указанного диапазона. `notCategories` запрещает ошибочные классы на выбранных диапазонах.
- Диагностики зацикливания и невалидного regex приводят к ошибке теста, даже если положительные ожидания прошли.
- Для каждого языка создаётся настоящий `EditorState`: внутри строки или комментария вставляется перенос строки, затем удаляется. Результат инкрементального разбора после каждого изменения сравнивается с полным разбором того же текста.

Oniguruma и грамматики настоящие; подменяется только браузерная загрузка WASM, чтобы тест мог прочитать установленный файл в Node.

## Сравнение с TextMate

`legacy.ts` независимо читает исходные TextMate-грамматики. `legacy-scope-map.json` содержит зафиксированную таблицу из `codemirror-textmate@1.1.0`, `dist/tmToCm.js` (MIT) и не импортирует production mapper.

Для языков, использующих TextMate в CM6, каждый ранее подсвеченный непробельный символ должен сохранить класс. Намеренные исправления задаются точными диапазонами `legacyChanges` с объяснением и положительными проверками новой подсветки. Для native-парсеров отличия записываются в отчёт, поскольку их классификация может обоснованно отличаться.

Грамматики берутся из текущего дерева. Это сравнение старого сопоставления scopes с адаптером CM6, а не архивный запуск всего CM5. Правки самих грамматик требуют отдельных regression-тестов.

## Границы проверки

Набор проверяет конкретные конструкции и категории токенов. Он не доказывает корректность всех возможных программ каждого языка. Статический список scopes грамматики тоже не является доказательством покрытия: часть правил применяется только во вложенных языках или недостижима в обычном документе.

Автоматически проверяются классы и обновление подсветки при редактировании. Визуальная проверка всех языков во всех темах отдельно не выполнялась. Данные для ручного просмотра подготовлены как Markdown-файлы текущего vault, а не через UI-импорт.

В native-режимах Pug и Textile остаются предупреждения об неизвестных дополнительных тегах (`indent`, `dot`, `heading-2`). Основные категории проверяются; эти предупреждения не приравниваются к ошибке токенизатора.
