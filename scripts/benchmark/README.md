# Изолированный benchmark massCode

Первый сценарий: **1000 Code + 1000 Notes + 1000 HTTP** (3000 записей).
Применяются реальные API handlers и serializers vault. Обычный профиль и уже запущенное приложение не используются. Подготовка создаёт отдельные production build, профиль и vault; существующий output отклоняется. Нужны установленные зависимости и Electron текущего проекта.

```sh
# Быстрый smoke: 10 записей суммарно (6/3/1)
pnpm bench:prepare --count 10
# Полный первый набор: 1000 в каждом пространстве
pnpm bench:prepare --space all --count 1000
# Используйте абсолютный output, напечатанный prepare
pnpm bench:start --output /absolute/run
pnpm bench:report --output /absolute/run
```

По умолчанию output — уникальный игнорируемый `docs/benchmarks/<run>`. `--output` позволяет выбрать новый каталог. `--seed` задаёт детерминированный контент. `--port` задаёт отдельный API порт (54321 по умолчанию): при конфликте выберите новый run с другим портом. `--space mixed` (по умолчанию) распределяет общее `--count` примерно 60/30/10%; `code`, `notes`, `http` создают одно пространство. Только `all` трактует count как число **на пространство**.

Code содержит по три фрагмента; тексты разных размеров (512/4096/32768 символов основы), notes содержит Markdown и fenced code, HTTP — JSON и локальный POST `http://127.0.0.1:5191/echo`. Для Send предварительно запустите `pnpm http:server`. Генерация проверяет контент каждой записи и итоговые количества. `seed.json` содержит размеры и SHA-256 содержимого; UUID и времена хранения зависят от запуска.

## Ручной протокол через Computer

1. Зафиксируйте ОС, нагрузку, режим питания и параллельно работающие приложения вместе с manifest.json. Окно теста имеет название `massCode BENCHMARK`. На macOS первый start создаёт отдельную копию Electron в `<run>/runtime/massCode Benchmark.app`, меняет только её bundle identity и подписывает ad-hoc через системный codesign. Для Computer выбирайте этот полный путь: он отделяет тест от уже запущенного dev-приложения. Копия требует дополнительного места на диске.
2. Проверяйте дерево HTTP также по скриншоту: виртуализированные строки могут отсутствовать в текстовом accessibility tree Computer. Запустите профиль; откройте Code, Notes, HTTP. Измерьте первое открытие списка и первой записи. Повторите открытия минимум 20 раз для p95; сохраните размер выбранных документов в ручных заметках протокола.
3. В Code/Notes ищите `needle`: первая поисковая загрузка в сессии, новые строки поиска и повторы той же строки разделены. HTTP sidebar фильтрует локально и имеет отдельную метрику. Search-first/new/repeat обозначает историю строк запросов только в памяти renderer, а не гарантированное состояние индекса/кэша.
4. Повторный запуск процесса допустим на том же профиле. Он сохраняет UI state и изменения. Для полностью исходных данных создайте новый output тем же seed. Автоматического удаления/restore нет. Кэш ОС не очищается, поэтому запуск после рестарта не называйте cold-disk benchmark.
5. Закройте только тестовое окно обычным выходом приложения, затем сформируйте отчёт. События также сбрасываются раз в секунду, но последний неполный интервал при аварийном завершении может потеряться.

## Что измеряется

- `startup.main-imported`: bootstrap до импорта main; `startup.renderer-document-loaded`: bootstrap до did-finish-load, не до готовности всех редакторов.
- `api.<domain>.<method>.<list|item|other>`: main bridge fetch и чтение response body; без renderer IPC transfer и paint. IDs, query и содержимое не записываются.
- `*.state-presented`: загрузка/присвоение состояния, Vue nextTick и следующий requestAnimationFrame. Это **не доказательство завершения paint**; debounce ввода поиска до вызова загрузчика не входит. Устаревшие результаты и ошибки имеют отдельный статус.
- `memory.jsonl`: process tree Electron при загрузке документа и первом успешном list/open каждого пространства; memory в единицах Electron (KB).

Статус `ok` подтверждает завершение операции без исключения, но не полноту данных: отдельно проверьте ожидаемое число записей и содержимое интерфейса. Пустой provisional-список нельзя считать готовой библиотекой.

Отчёт показывает n, медиану, максимум, p95 только при n ≥ 20. Не смешивайте разные размеры данных/условия в одном выводе. Это пилот, а не маркетинговый предел вместимости. Save durability, end-to-end Send, профили CPU и отрисовка сложных документов требуют отдельного протокола и пока не измеряются.

Инструментирование выключено без валидного marker и изолированного профиля. Данные renderer принимаются только от доверенного main frame и по списку разрешённых метрик. Обновления и регистрация системного протокола отключены только для валидного benchmark запуска. Сбор использует секундный буфер; накладные расходы присутствуют и должны учитываться при сравнении.

Проверка утилит: `pnpm exec vitest run scripts/benchmark/common.test.ts`.
